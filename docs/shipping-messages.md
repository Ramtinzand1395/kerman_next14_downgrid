# حذف پیام‌های تکراری ارسال و هماهنگی قیمت داشبورد

برنچ: `fix/admin-api-access-policy` — ۵ نوامبر ۲۰۲۶

## تغییرات نمایشی

- بلوک توضیحات همهٔ روش‌های ارسال از ابتدای سبد و صفحهٔ محصول حذف شد.
- توضیح تکراری ارسال از خلاصهٔ سبد و خلاصهٔ پرداخت حذف شد؛ ردیف مبلغ ارسال باقی است.
- توضیحات طولانی زیر تک‌تک روش‌های ارسال در پرداخت حذف شد؛ نام روش و مبلغ آن نمایش داده می‌شود. فقط برای روش انتخاب‌شده با پرداخت هنگام تحویل، یک یادآوری کوتاه نمایش داده می‌شود.
- پیام‌های اضافهٔ «انتخاب آدرس الزامی است»، «تضمین امنیت اطلاعات ارسال»، «روش و هزینه بر اساس شهر مقصد» و تکرار توضیح روش پرداخت حذف شدند. اعتبارسنجی آدرس، خطاها و دکمه‌های ادامه/پرداخت حفظ شده‌اند.
- توضیحات فنی تکراری درباره ذخیره مبلغ نامشخص از فرم تنظیمات ارسال حذف شد.
- متن شرایط ارسال فقط در صفحهٔ قوانین باقی است و مبلغ شهری را از تنظیمات فعلی می‌گیرد.

## قیمت و ذخیره‌سازی

مبلغ `localDelivery.feeToman` همچنان از داشبورد قابل تغییر است؛ روی ۱۲۰ هزار تومان ثابت نشده است. اختلاف قبلی از توضیح مستقلی می‌آمد که عدد قدیمی ۱۵۰ هزار تومان را در خود داشت.

اکنون هنگام خواندن تنظیمات، توضیح ارسال شهری از مبلغ عددی ساخته می‌شود؛ توضیح قدیمی ذخیره‌شده نمی‌تواند مبلغ متفاوتی را به نمایش برساند. محاسبه روش ارسال نیز مستقل از متن ورودی، توضیح را از همان مبلغ می‌سازد. در ذخیره داشبورد، متن تولیدشده کنار عدد فعلی ذخیره می‌شود و فیلد ویرایش آزاد این توضیح از داشبورد حذف شده است. API برای سازگاری با کلاینت قبلی، توضیح قدیمی را می‌پذیرد اما آن را مبنای قیمت یا متن جدید قرار نمی‌دهد.

مقادیر پیش‌فرض مدل و خواندن تنظیمات به یک مقدار مشترک ارجاع می‌دهند. قیمت سفارش‌های قبلی از snapshot همان سفارش خوانده می‌شود؛ تغییر تنظیمات، سفارش پرداخت‌شده را مجدداً قیمت‌گذاری نمی‌کند. هزینه روش‌های پس‌کرایه همچنان نامشخص و هنگام تحویل است و به‌صورت ارسال رایگان ثبت نمی‌شود.

## تست

قبل از اصلاح، سه تست اختلاف متن قدیمی با مبلغ فعلی شکست خوردند. شش تست جدید در `shipping-messages.test.mjs` اضافه شده است:

- خواندن تنظیمات با مبلغ ۱۲۰ هزار و متن قدیمی ۱۵۰ هزار، بدون نوشتن در دیتابیس.
- محاسبه روش ارسال با متن قدیمی ورودی.
- اجرای واقعی handler ذخیره/خواندن داشبورد با مدل mock، برای مبالغ ۱۲۰، ۱۷۵ و ۲۱۰ هزار تومان.
- رد قیمت صفر، منفی، اعشاری و خارج از محدوده بدون ذخیره و حفظ مبلغ سفارش قدیمی.
- ذخیره داشبورد بدون نیاز به ارسال فیلد توضیح قیمت.
- اجرای واقعی API روش‌های ارسال و صفحهٔ قوانین، پیش و پس از تغییر قیمت داشبورد.

تست‌های موجود ساختار دادهٔ محصول و سیاست مرجوعی نیز پاس شدند؛ حذف متن‌های تکراری، قیمت کالا و JSON-LD را تغییر نداده و نرخ ساختگی ارسال به سئو اضافه نشده است.

نتیجه: `npm test` شامل ۲۱۵ تست موفق، صفر شکست و یک تست اختیاری POS اجرا‌نشده است؛ بررسی TypeScript و build نیز موفق بودند. هشدار قبلی `<img>` در Footer باقی است. اجرای تست اختصاصی:

```bash
node --test shipping-messages.test.mjs shipping-policy.test.mjs merchant-schema.test.mjs
```

هیچ دیتابیس واقعی در این کار خوانده یا تغییر داده نشد. متن قدیمی پس از انتشار کد، در خواندن نادیده گرفته می‌شود و با ذخیره بعدی تنظیمات، متن هماهنگ جای آن را می‌گیرد. تغییرات فقط در همین برنچ آماده می‌شوند و merge یا deploy به `main` انجام نشده است.
