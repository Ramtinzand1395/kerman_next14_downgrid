# اصلاح سرریز صفحهٔ دریافت نوبت

برنچ: `fix/admin-api-access-policy` — ۵ نوامبر ۲۰۲۶

## بازتولید و علت

روی build محلی در Chromium، در عرض پنجرهٔ ۱۳۶۳ پیکسل، `document.documentElement.scrollWidth` دقیقاً ۱۴۳۰ پیکسل شد. ستون محتوا از سمت چپ بیرون صفحه می‌رفت.

ستون اصلی پروفایل با `280px 1fr` تعریف شده بود. حداقل عرض خودکار ستون `1fr` از محتوای مراحل داخلی بزرگ‌تر می‌شد و اجازهٔ کوچک‌شدن ستون را نمی‌داد. در عرض‌های میانی نیز نمایش هم‌زمان منوی کامل هدر، جست‌وجو و کنترل‌های حساب، سرریز جداگانه‌ای ایجاد می‌کرد.

## تغییرات

- ستون محتوای پروفایل به `minmax(0, 1fr)` تغییر کرد و روی والدهای محتوا `min-w-0` قرار گرفت.
- عرض نوار مراحل محدود شد و اسکرول آن داخل خود نوار باقی می‌ماند.
- چیدمان فرم و خلاصه تا پیش از breakpoint برابر ۱۲۸۰ پیکسل تک‌ستونه است؛ از آن عرض به بعد کنار هم قرار می‌گیرند.
- عرض ریشهٔ فرم، خلاصه و فهرست روزها به والد محدود شد. متن بلند و بدون فاصله، مانند آدرس آزمایشی، به خط بعد می‌رود.
- منوی جمع‌شوندهٔ موجود هدر تا پیش از ۱۲۸۰ پیکسل استفاده می‌شود؛ منوی کامل و جست‌وجوی دسکتاپ از آن عرض نمایش داده می‌شوند.

از مخفی‌کردن سراسری overflow برای پوشاندن ایراد استفاده نشده است. ستون‌ها واقعاً در عرض موجود جا می‌گیرند. منطق انتخاب بازی، ظرفیت، قیمت و ثبت نوبت تغییری ندارد.

بررسی TypeScript و `npm run build` موفق بودند؛ هشدار قبلی `<img>` در Footer باقی است. برای این تغییر صرفاً نمایشی، تست مقایسهٔ کلاس‌های CSS اضافه نشد؛ خود چیدمان واقعی در مرورگر اندازه‌گیری شد.

مرورگر با نشست و پاسخ‌های API آزمایشی محلی اجرا شد. هیچ درخواست واقعی، سفارش یا نوبتی ثبت نشد و دیتابیس production در دسترس تست نبود. تغییرات فقط در این برنچ آماده می‌شوند و merge/deploy به `main` انجام نشده است.
