# پاک‌سازی محتاطانهٔ کدهای بلااستفاده

برنچ: `fix/admin-api-access-policy`
مبنای پاک‌سازی: `10ad84a`.

## حذف فایل‌های بدون مصرف

تحلیل import/re-exportهای TypeScript و جستجوی مستقل مصرف‌کننده‌ها نشان داد این فایل‌ها در صفحه، API، worker، اسکریپت عملیاتی یا تست‌ها مصرف نمی‌شوند:

- `app/(dashboard)/dashboard/appointments/_components/CourierQueue.tsx`: صف قدیمی پیک.
- `app/components/notifications/AdminNotificationComposer.tsx`: فرم قدیمی اعلان؛ فرم فعلی `CampaignComposer` است.
- `lib/dashboard-report-policy.ts`: توابع قدیمی گزارش؛ مسیر گزارش فعلی از `dashboard-report.ts` استفاده می‌کند.
- `helpers/CheckPhoneAction.ts`: اکشن قدیمی بدون فراخوانی.
- `app/(dashboard)/dashboard/components/modals/index.ts`: فایل تجمیع خروجی بدون مصرف؛ خود ویرایشگرها باقی هستند.
- `app/(public)/my-profile/MyOrders.tsx`: نسخهٔ قدیمی سفارش‌ها که فقط import بلااستفاده داشت. صفحهٔ پروفایل از `MyOrdersTabs` و سپس `MyStoreOrders` و `MyGameOrders` استفاده می‌کند.

مجموع این شش فایل ۷۷۵ خط بود. ابزار مهاجرت `lib/gamelist-migration.mjs` حفظ شد، چون اسکریپت عملیاتی و تست آن را استفاده می‌کنند.

## پاک‌سازی داخل فایل‌های فعال

- صفحه‌بندی محلی بدون فراخوانی از پنل نوبت‌ها حذف شد؛ صفحه‌بندی فعال جدول باقی است.
- تب نوعی قدیمی courier، حالت `courierMode` که همیشه false بود، وضعیت فیلتر پنهان و خروجی‌های مخصوص صف حذف‌شده پاک شدند. تغییر وضعیت پیک در درخواست‌ها و فیلترهای فعال خدمت، وضعیت، تاریخ و جستجو برقرار هستند.
- importها و محاسبات استفاده‌نشده حذف شدند. در متادیتای محصول فقط متغیر قیمت بلااستفاده حذف شد؛ قیمت استفاده‌شده برای JSON-LD و نمایش محصول حفظ شد.
- prop نادیده‌گرفته‌شدهٔ `onRetry` از نمودار توزیع حذف شد؛ دکمه‌های تلاش مجدد در حالت خطای واقعی باقی هستند.
- تابع بدون فراخوانی `normalizeOrderList` حذف شد؛ منطق فعال ثبت سفارش حضوری دست‌نخورده است.
- پارامترهای درخواستِ استفاده‌نشده به `_req` تغییر نام یافتند؛ تعداد و جایگاه آرگومان‌های API حفظ شد.
- از مسیرهای قدیمی چاپ، importها و کدهای احراز هویت کامنت‌شده/بدون فراخوانی حذف شدند. مسیرها، مجوزهای اجرایی فعلی، payload، پاسخ و عملیات صف چاپ تغییر نکرده‌اند. نتیجهٔ `PrintQueue.create` دیگر به متغیر بی‌مصرف نسبت داده نمی‌شود، ولی خود ذخیره انجام می‌شود.
- دو دستور npm که فایل مقصد نداشتند، `seed` و `audit:referral`، حذف شدند. وابستگی‌ها و package-lock تغییر نکردند.

## صفحهٔ خدمات

بخش راهنمای داخلی نگارش مقالهٔ سئو و بلوک شمارهٔ ساختگی `۰۳۴-XXXXXXXX` حذف شدند. هر شش دکمهٔ واقعی، موضوع فرم تماس، راهنمای ارسال و اطلاعات تماس واقعی در فوتر و صفحهٔ تماس حفظ شدند.

## اعتبارسنجی

- تمام ۳۱ فایل تست موجود حفظ شدند؛ هیچ فایل تست یا وابستگی تست حذف یا به پروژه اضافه نشد.
- کل تست‌ها: ۲۳۷ مورد؛ ۲۳۶ موفق، صفر شکست، یک تست اختیاری POS اجرا نشده.
- بررسی TypeScript با `--noUnusedLocals --noUnusedParameters` بدون خطا انجام شد؛ ۳۱ مورد ممیزی قبلی رفع شدند.
- تحلیل وابستگی پس از پاک‌سازی: شش فایل تأییدشده حذف شده‌اند؛ ابزار مهاجرت خارج از مسیر اجرای سایت به‌درستی به‌عنوان مصرف‌شده در CLI و تست شناخته می‌شود.
- بیلد production و lint موفق هستند؛ تنها هشدار بیلد مربوط به تصویر Footer از قبل است.
- قرارداد API چاپ قبل و بعد در ۹ سناریو با مدل آزمایشی مقایسه شد: GET خالی، null، دارای کار و خطا؛ POST موفق و خطا؛ DELETE موفق، کار ناموجود و خطا. وضعیت HTTP، بدنهٔ پاسخ، payload و ترتیب عملیات ذخیره‌سازی برابر بودند. اتصال واقعی یا درخواست به API چاپ سایت انجام نشد.
- مرورگر محلی در عرض‌های ۳۹۰ و ۱۳۶۳: لودینگ، جزئیات و تاریخچهٔ نوبت، کنترل‌های تنظیمات و پاداش، اطلاعات تماس و نقشه، شش مقصد خدمات، فرم تماس و رفت‌وبرگشت ورود بررسی شدند. نبود متن سئوی داخلی و شمارهٔ ساختگی نیز بررسی شد.

تغییرات محدود به همین برنچ هستند؛ هیچ دیتابیس واقعی، `main` یا production تغییر نکرده است. این پاک‌سازی شامل همگام‌سازی با کامیت‌های جدید `main` نیست.
